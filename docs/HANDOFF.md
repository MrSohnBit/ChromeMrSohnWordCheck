## 단축키 구현의 정확한 한계

Chrome에는 확장이 단축키를 직접 재지정하는 API가 없습니다. `proofread` command 이름·기본 suggested_key는 유지합니다.

v1.0.13은 실제 키를 읽어 `lastProofreadShortcut`에 저장합니다. 등록이 없으면 KEY 배지로 표시하고, 이전 정상 키가 있는 상태에서 업데이트/브라우저 시작 이벤트를 받으면 단축키 설정 화면으로 안내합니다. **자동 재등록이나 절대 해제 방지가 아닙니다.** 사용자가 의도적으로 단축키를 해제한 것과 오류로 해제된 것을 구별하지 못합니다.

## 검증 근거

- 실제 API: 예시 문장 교정 성공. 사용자 키 원문은 저장하지 않음.
- 실제 tmaadm 메시지 페이지: 단축키로 모달과 교정 결과 표시 확인.
- 실제 maadm 12155·12148 검수 페이지: 두 검사 버튼 표시, 새 탭 재접속 시 자동 표시 확인.
- 실제 서버 변수 저장·승인·반려는 실행하지 않음.
- Node 테스트 17개 통과 기록. 하이라이트/취소/변경된 원문 보호/버튼 선택 등은 mock 브라우저 테스트와 구분해서 해석할 것.
- [QA.md](../QA.md)는 시점별 이력. 예전 절의 “미검증/권한 대기/심볼릭 링크”는 당시 상태이며 현재 상태가 아님.

## 후속 작업에서 확인할 사항

- 임의 사이트·iframe·리치 에디터 호환은 미완료. 사용자가 요청하면 대상별 검증 필요.
- `tests/settings-browser.cjs`는 과거 옵션 화면 mock으로, 이후 추가된 commands·permissions API에 맞게 보강한 뒤 현재 통과 여부를 판단해야 함.
- 브라우저 테스트와 API 테스트는 서로 다른 범위. 실서버를 mock 성공으로 대체하지 않음.
- 실행 사본 동기화/ZIP 자동화는 v1.0.14의 tools/release.py로 구현됨. 파일 변경 후 --publish를 명시적으로 실행.
- 개발 소스 머지 요청은 사용자가 취소. Android 저장소나 다른 브랜치를 건드릴 미완료 작업은 없음.
